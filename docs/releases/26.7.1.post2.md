> [!IMPORTANT]
> Windows installations of `26.7.1.post1` and earlier cannot apply this release
> through `conda self update`. Their legacy conda-ship readers cannot validate
> the PE runtime-data layout introduced by conda-ship 0.9.0.

This release rebuilds all native executables with conda-ship 0.9.0. The macOS
artifacts now pass strict native signature validation, and the Windows runtime
data uses the `.cship` anchor that a downstream Authenticode signature covers.

The GitHub release includes the Windows executable and installer. The Windows
update package is published as
`win-64/conda-runtime-v2-26.7.1.post2-0.conda`. No 0.9-format Windows package is
published under the legacy `conda-runtime` name, so existing Windows runtimes
do not discover an update they cannot stage.

To install this release on Windows, close conda, preserve and move aside the
old executable and managed prefix, then run `install.ps1`. The default managed
prefix is `$env:LOCALAPPDATA\conda\runtime`. If `CONDA_SHIP_PREFIX` is set, use
a new empty location. Reusing the old direct-install metadata is rejected.

Fresh `26.7.1.post2` Windows installations record the new
`conda-runtime-v2` source and can apply later native packages published under
that name. Publishing any 0.9-format Windows package under the legacy source
would break root updates from remaining 0.8.0 runtimes.

Linux and macOS native update packages remain available through the existing
channel.
